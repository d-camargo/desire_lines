name=Desire Lines
qgisMinimumVersion=3.0

supportsQt6=True
description=The Desire Lines plugin for QGIS is a tool designed to create and visualize desire lines, which are graphical representations of preferred or anticipated movement paths between points on a map.
version=0.7.4
author=Diego Camargo
email=dg.camargo@proton.me

about=The plugin helps users illustrate movement patterns, such as travel routes, pedestrian flows, or migration paths, allowing for a clearer understanding of spatial dynamics. By visualizing these paths, the plugin aids in urban planning, transportation analysis, and spatial studies, providing insights into how people or objects move between locations. The "Alocacao em rodovias" tab assigns traffic over the real highway network with HCM capacity; it targets rural/interurban highways (not urban streets) and requires the GisBR plugin to download the official network.

changelog=
    0.7.4
    - Fix: plugin dialogs no longer use the blocking exec() call; the GISBR notice now opens window-modal without blocking QGIS.
    - Passes the plugins.qgis.org security scan (0.7.2 and 0.7.3 were not published).
    0.7.3
    - Fix: errors are no longer silently swallowed when reading link attributes; a missing link id field now raises a clear error instead of falling back to feature ids.
    0.7.2
    - Fix: QGIS no longer asks to install GISBR when it is already installed (plugin_dependencies removed from metadata).
    - When GISBR is missing, a single window suggests installing it, with a shortcut to the Plugin Manager and a "Don't show again" option.
    0.7.1
    - Fix: centroid connectors no longer appear in the assignment output layer (AoN, MSA, FW).
    - Fix: link_id is written as an integer field when the source id is numeric (text only for non-numeric id fields).
    0.7.0
    - Frank-Wolfe equilibrium traffic assignment method with exact line search.
    - Highway layer parameters: capacity, free-flow time, and one-way direction read directly from layer attributes (overriding HCM calculation).
    - Mapped fields in the traffic panel are properly resolved (previously fell back silently to default).
    - Link-level BPR alpha and beta parameters applied per arc.
    - Updated convergence defaults to 100 iterations and 0.001 relative gap.
    - End-to-end benchmark regression validation against Sioux Falls user equilibrium reference dataset.
    0.6.2
    - Fix: highway assignment drew connections that do not exist in the network where network nodes are close together. Each centroid is now anchored to the nearest point of the nearest link (the link is split there) instead of the nearest node, and the connector carries the zone's trips.
    - Warnings for long connectors, centroids sharing a node or link, ambiguous anchoring and the zones left unconnected.
    - Output layer: new "tipo" field (link, link_dividido, conector); connectors are drawn as grey dashed lines.
    - The run stops with a clear message when a layer's coordinates do not match its CRS label.
    0.6.1
    - Fix: highway assignment no longer creates links that do not exist in the network when the layer is in a geographic CRS (e.g. GisBR EPSG:4674, EPSG:4326) — the network is now reprojected to a metric CRS before snapping, lengths and connectors.
    - Fix: zone connectors can no longer be chained into a shortcut between two network nodes.
    - Regression test on the Sioux Falls benchmark network.
    0.6.0
    - Single toolbar button with drop-down menu.
    - GisBR download by metropolitan area, micro-region, meso-region and health macro-region.
    - State road network picked from the GisBR catalogue (adds Goiás).
    - Fix: assignment output layer now opens (layer name was `None` and a layer source in the output field duplicated the path).
    0.5.0
    - Highway traffic assignment moved to a dockable panel.
    - HCM parameters organized into a dedicated tab.
    - Scrollable pages added for improved interface flexibility.
    - Removed highway traffic assignment tab (Tab 4) from the main dialog.
    0.4.0
    - New "Alocacao em rodovias" tab: traffic assignment over the real highway network (official DNIT/SNV and DER mesh via the GisBR plugin) with per-direction capacity computed by HCM 6th ed. procedures (ch. 15 two-lane, ch. 12 multilane/freeway).
    - Two assignment methods, same inputs and same outputs: All-or-Nothing (single pass, no capacity restraint) and Equilibrium MSA + BPR (iterative, with relative gap).
    - Separate "Compute capacity" action: returns the mesh with capacidade and the src_* provenance of every parameter, before any assignment.
    - Output layer carries volume, capacidade, v/c, approximate LOS (by v/c band), time, delay, method, scope and per-parameter provenance, styled by v/c.
    - Missing HCM parameters are never assumed silently: each has a documented default, is overridable globally or by layer field, and its effective source is recorded.
    - Urban crossings inside the highway mesh are flagged escopo='urbano' and counted with a warning: urban capacity follows a different procedure and is out of scope.
    0.3.2
    - Fix Qt6 enum-scoping compatibility issues for QGIS Plugin Repository.
    0.2.0
    - New "AoN (Delaunay)" tab: All-or-Nothing allocation over a Delaunay network of zone centroids, following least-cost paths. Optional "Split by direction" output (flow_ab / flow_ba).
    - Automatic metric CRS selection for routing (UTM zone, or SIRGAS 2000 / Brazil Albers EPSG:10857 for wide areas).
    - Inputs can be assigned from existing project layers; no longer tied to imported-layer names.
    - Configurable output GeoPackage with sensible fallback, plus live input validation.
    - Desire lines and AoN flows styled with a graduated (Natural Breaks) renderer, fully editable from the Symbology panel.
    0.1.0
    - Initial release: build OD desire lines from a CSV matrix and traffic-zone centroids.
